## 1. 文件定位與判讀原則

本文件依 UI 參考圖整理視覺語言與可重用元件，目的是讓後續頁面維持一致，不代表所有數值或產品行為已定案。

- **可確認**：參考圖中可直接觀察到的結構、相對層級、元件種類與視覺方向。
- **建議值**：未經設計原檔或量測工具確認，為方便工程實作而提出的起始值；導入前應再與設計稿校準。
- **待確認**：僅憑單張靜態圖無法判定的規則，例如斷點、權限、完整狀態、鍵盤操作與資料上限。
- 參考圖中的日文片名、人物、標籤、信心分數及版本時間均視為示意資料，不構成正式內容模型。

## 2. 視覺風格

### 2.1 整體方向（可確認）

- 明亮、低彩度、帶輕微科技感的內容管理介面。
- 頁面背景使用暖灰至冷白的柔和漸層；主要資訊承載於白色或半透明白色卡片。
- 左側導覽沒有深色實心背板，使用接近白色的浮層感與大圓角。
- 深海軍藍作為主要操作與選取狀態；藍、綠、橙、紫作為不同語意的輔助色。
- 大量留白、細邊線、柔和陰影與膠囊形控制項，降低高密度資料的壓迫感。
- 資訊層級依序為：頁面背景 → 模組卡片 → 群組列／分段控制 → Chip、Badge 與文字。

### 2.2 設計原則

1. **任務優先**：標題、狀態、主要操作與內容資料應在首屏內可掃讀。
2. **高密度但不擁擠**：以卡片分區、對齊與固定間距取代大量分隔線。
3. **AI 結果可追溯**：生成內容應可顯示來源、信心程度、採用狀態及可編輯入口。
4. **狀態不只靠顏色**：顏色需搭配圖示、文字或形狀，照顧色覺差異。
5. **跨模組一致**：Video、AI Chapter、場景與章節、AI Search 共用同一套殼層、Tab、卡片、表單及狀態語言。

## 4. Layout

### 4.1 App Shell（可確認）

- 左側固定 Sidebar，右側為主要工作區。
- 工作區由頂部 Header、內容識別區、頁內 Tab 與下方雙欄內容構成。
- Sidebar、Header 控制項與主內容卡片皆呈浮層感。
- 參考圖是 1536px 寬桌面畫面；未展示平板及手機版。

### 4.2 桌面配置（建議值）

| 區域 | 建議值 | 說明 |

## 5. 導覽元件

### 5.1 Sidebar

#### 結構（可確認）

1. 品牌區：彩色光暈標誌、`KK lab`、副標 `OTT Content Intelligence`。
2. 一級導覽：首頁、影片庫、AI 分析。
3. 展開中的內容管理群組：群組標題及向上 Chevron。
4. 二級導覽：基本資訊、AI 標籤、分段＆章節、場景與章節、封面管理、演員與成效。
5. 分隔後的工具入口：AI 搜尋預覽、分析報表。
6. 底部固定：設定。

#### 視覺與行為

- 一級項目採圖示＋文字；目前群組可使用白色浮層及陰影強調。
- 二級選取項採淡藍背景、藍色文字與大圓角；參考圖沒有左側色條。
- 建議一級項高度 `44px`、二級項高度 `42px`、水平內距 `16px`。
- Hover、Focus、收合、權限不可用及超長文字截斷狀態待確認。
- `Video` 與 `AI Search` 的資訊架構應沿用相同展開／收合規則，不另造視覺語言。

### 5.2 Header

#### 可確認元素

- 左側：返回按鈕、麵包屑（例如「返回影片庫 / AI 標籤」）。
- 右側：版本下拉、重新分析、主要儲存按鈕、更多操作。

#### 建議規格

- Header 背景保持透明或弱表面色，讓主內容成為視覺焦點。
- 返回按鈕需有至少 `40 × 40px` 點擊區。
- 版本下拉使用低對比 Outline；主要操作「儲存」使用深藍實心樣式。
- 重新分析屬可能耗時或覆蓋結果的操作，觸發前是否需確認、分析中是否可離開均待確認。
- 未儲存、儲存中、儲存成功、儲存失敗與版本衝突狀態必須補齊。

### 5.3 頁內 Tab

- 參考圖中的頂層內容 Tab 包含：Content 層級標籤、片段層級標籤、分段＆章節、場景與章節、演員、字幕、相似內容。
- 外層為白色膠囊容器；目前 Tab 為深藍實心膠囊，其他 Tab 保持透明。
- 建議高度 `44px`，容器內距 `4px`，單項最小水平內距 `20px`。
- Tab 切換需保留未儲存內容、鍵盤方向鍵操作與焦點指示；切換是否改變 URL 待確認。
- 未來 AI Chapter、場景與章節及 AI Search Detail 應沿用相同 Tab 元件，但避免塞入過多一級頁籤；超過 7 項時評估二級導覽或 Overflow。

## 6. 基礎元件

### 6.1 Card

#### 類型

- **Module Card**：承載完整功能區，如「AI 產生標籤」、「內容概要」。
- **Row Card**：模組內單一資料群組，如類型、主題、情緒、風格、目標受眾。
- **Info Grid Card**：以等寬欄位呈現語言、字幕、集數、片長等 metadata。
- **Evidence Card**：呈現 AI 標籤來源與依據。

#### 建議規格

- Module Card：`20px` 圓角、`20–24px` 內距、細邊線與柔和陰影。
- Row Card：上下 `16px`、左右 `16–20px`；相鄰列以邊線或 `8px` 間距區隔，二擇一。
- Card 標頭包含標題、說明、狀態或操作；標題與操作需保持同一基線。
- Loading 使用與最終排版同尺寸 Skeleton，避免跳動。

### 6.2 Button

| 類型 | 視覺 | 典型用途 |
| --- | --- | --- |
| Primary | 深藍底、白字 | 儲存、確認 |
| Secondary | 白／半透明底、深色字、細邊線 | 重新分析、編輯 |
| Ghost | 透明底、深色圖示或文字 | 返回、更多操作 |
| AI Action | 白底、陰影、前置 AI／加號圖示 | 從片段生成建議 |
| Destructive | 紅色語意 | 刪除；參考圖未展示，待確認 |

- 建議高度：一般 `40px`、緊湊 `32px`、大型 `44px`。
- Icon-only Button 建議最小 `40 × 40px`，並提供可讀取的名稱。
- 狀態至少包含 Default、Hover、Pressed、Focus-visible、Disabled、Loading。
- Loading 時保留按鈕寬度；有副作用的操作需避免重複觸發。

### 6.3 Tag／Chip

參考圖的標籤 Chip 同時承載名稱、信心分數與採用狀態。

- **Selected AI Tag**：淡藍背景、深藍文字、左側實心圓勾、右側百分比。
- **Candidate Tag**：淺灰背景、灰色文字、左側空心／淡色勾、右側百分比。
- 建議高度 `28–32px`、左右內距 `10–12px`、項目間距 `8px`。
- 標籤文字過長時建議單行省略並以 Tooltip 顯示全文；是否允許換行待確認。
- 百分比應有明確語意名稱，例如 `AI 信心分數 98%`；門檻與排序規則待確認。
- 可選 Chip 不應只靠底色表達選取，需保留勾選圖示與可讀取狀態。

### 6.4 Checkbox

- 參考圖以 Chip 左側的圓形勾選控制呈現，視覺上不是傳統方形 Checkbox。
- 若功能語意是「多選」，程式語意仍建議採 Checkbox，外觀可客製為圓形。
- 建議尺寸 `16–18px`，選取態深藍底白色勾，未選態白／灰底加細邊線。
- 狀態：未選、已選、部分選取（若有群組）、Hover、Focus、Disabled、Error。
- 點擊整個 Chip 應可切換，並保留清晰焦點框與鍵盤 Space 操作。

### 6.5 Badge

- **Status Badge**：例如綠色圓點＋「已完成分析」。
- **Source Badge**：例如「AI 生成」，使用中性灰底，避免與操作按鈕混淆。
- **Count Badge**：例如「已選 2/6」，可採純文字或低對比膠囊。
- 建議高度 `24–28px`、圓角 `999px`、字級 `12px`。
- 狀態文案與顏色需建立一對一規則；「分析中」、「待分析」、「失敗」、「部分完成」待產品確認。

### 6.6 圖片縮圖

- 內容識別區使用橫向 16:9 縮圖，帶 `12px` 左右圓角。
- 右側內容摘要使用較大的接近 4:3 圖片；實際素材比例待確認。
- 推薦封面列使用小型橫向縮圖，下方附標籤，並支援水平瀏覽。
- 影片縮圖可疊加播放按鈕；多個播放圖示同時出現時需確認各自播放範圍。
- 所有圖片需提供替代文字、Lazy loading、預設佔位、載入失敗與成人／敏感內容遮罩（若產品需要）。
- 建議 `object-fit: cover`；焦點裁切位置與影像安全區待確認。

### 6.7 表單

參考畫面主要呈現檢視與選擇狀態，完整輸入表單未展示；下列為延伸建議。

- 欄位統一採 Label → Control → Helper／Error 的垂直結構。
- 建議控制項高度 `40px`，多行文字最小高度 `96px`，圓角 `10–12px`。
- Default 使用白底細邊線；Focus 使用藍色外框；Error 使用紅色邊線及文字訊息。
- 必填不可只用顏色區分；唯讀與 Disabled 視覺需明確不同。
- AI Search Detail 的招呼語、外觀與資料管理應使用同套欄位、分段控制、Switch、上傳及儲存列。
- 自動儲存或手動儲存、離頁提醒、版本回復及權限限制待確認。

### 6.8 內容標籤列（Tag Category Row）

每列由五個區域組成：

1. **類別圖示**：帶語意色的圓形底，例如愛心、文件、笑臉、星光、人群。
2. **類別名稱**：中文主名＋英文輔名，例如「類型 Genre」。
3. **類別說明**：一句短描述，例如「影片的主要類型與風格」。
4. **標籤集合**：已選與候選 Chip，依重要度由左至右排列。
5. **列操作**：右上顯示「已選 2/6」及 Overflow Menu。

#### 建議行為

- 整列最小高度 `104px`；圖示區寬度固定，文字區建議 `140–160px`，Chip 區彈性成長。
- 標籤超過一行可換行，列高隨內容增加；不建議橫向捲動核心選項。
- Overflow Menu 可承載重新生成、查看依據、清除選取等操作；實際選項待確認。
- 最低／最高選取數、手動新增、自訂標籤、重複名稱與敏感詞處理均待確認。

## 7. 狀態與互動

### 7.1 通用狀態

所有可互動元件至少需定義：

- Default、Hover、Pressed、Focus-visible、Disabled。
- Loading、Empty、Success、Warning、Error。
- Unsaved、Saving、Saved、Save failed（涉及資料編輯時）。
- No permission、Read only（若有角色權限）。

### 7.2 回饋原則

- 即時操作可用局部狀態或 Toast 回饋；不可只在頁首顯示遠離操作點的訊息。
- 超過約 1 秒的 AI 操作應顯示進度／處理中狀態；是否能取消待確認。
- 錯誤訊息需說明發生位置、影響與下一步，並保留使用者尚未提交的內容。
- 成功狀態避免長時間遮擋內容；版本或儲存時間可在 Header 輕量呈現。
- 破壞性操作應說明影響範圍；能復原時優先提供 Undo。

### 7.3 無障礙基準（建議）

- 文字與背景對比至少符合 WCAG AA；小字與淡灰 Chip 是優先檢查項。
- 鍵盤焦點必須可見，Focus ring 不應被圓角容器裁切。
- 點擊／觸控目標建議不小於 `40 × 40px`，行動裝置建議 `44 × 44px`。
- 圖示按鈕、狀態點、縮圖播放與百分比提供可讀取名稱。
- 支援 `prefers-reduced-motion`；不可用動畫作為唯一狀態提示。

## 8. Content-level Tag 畫面拆解

### 8.1 頁面層級

```text
App Shell
├─ Sidebar
└─ Workspace
   ├─ Header：返回／麵包屑／版本／重新分析／儲存／更多
   ├─ Content Identity Card
   │  ├─ 影片縮圖＋播放
   │  ├─ 片名
   │  ├─ 分析完成 Badge
   │  └─ ID／類型／年份／片長／集數等 Metadata
   ├─ Content Tabs
   └─ Two-column Content
      ├─ AI Generated Tags Card
      │  ├─ 標題／說明／從片段生成建議
      │  ├─ 類型 Genre
      │  ├─ 主題 Theme
      │  ├─ 情緒 Mood
      │  ├─ 風格 Style
      │  ├─ 目標受眾 Audience
      │  └─ 標籤摘要（AI 生成）
      └─ Context Column
         ├─ 內容概要 Card
         │  ├─ 編輯
         │  ├─ 圖片／AI 生成 Badge／劇情簡介
         │  └─ 語言／字幕／集數／片長／年份／地區
         ├─ AI 標籤來源與依據 Card
         │  ├─ 劇情摘要
         │  ├─ 片段分析
         │  ├─ 字幕文字
         │  └─ 視覺畫面
         └─ 建議相關封面關鍵字 Card
```

### 8.2 核心資料與責任邊界

- `ContentIdentity`：內容識別、版本及分析總狀態。
- `TagCategory`：類別名稱、圖示、描述、選取限制及標籤清單。
- `TagOption`：標籤名稱、信心分數、選取狀態、來源與是否可編輯。
- `TagSummary`：由已採用標籤生成的自然語言摘要；是否可手動覆寫待確認。
- `ContentSynopsis`：劇情簡介與基本 metadata；資料來源及編輯權限待確認。
- `TagEvidence`：劇情、片段、字幕與視覺來源；需能回到原始時間碼或文字範圍的需求待確認。
- `CoverKeywordSuggestion`：關鍵字、代表圖與關聯理由；是否直接連動封面搜尋待確認。

### 8.3 建議互動流程

1. 使用者檢視 AI 產生的候選標籤與信心分數。
2. 使用者以 Checkbox Chip 採用或取消標籤。
3. 使用者可開啟來源與依據，理解標籤產生原因。
4. 變更後標籤摘要可重新生成或標示為待更新；觸發時機待確認。
5. 使用者按「儲存」建立新版本或更新現有版本；版本策略待確認。
6. 重新分析可能覆蓋候選結果，需先說明對人工選取與摘要的影響。

## 9. 模組擴充一致性

### 9.1 AI Chapter

- 沿用 App Shell、內容識別區、版本、狀態 Badge 與頁內 Tab。
- 章節列表可重用 Row Card；章節名稱、時間碼、摘要與信心程度沿用 Typography、Chip 及 Badge。
- 建議補充 Timeline／播放器同步元件，但顏色與狀態必須沿用本系統。
- 自動切章、人工合併／拆分、拖曳排序及時間碼衝突規則待確認。

### 9.2 場景與章節

- 以縮圖、時間碼、場景標籤與章節歸屬組合 Card，可重用圖片縮圖與內容標籤列。
- 場景層級與章節層級應用層級、縮排或分組表達，不另增新的主色。
- 大量場景需規劃虛擬捲動、篩選與批次操作；規模上限待確認。

### 9.3 AI Search List

- 沿用 Sidebar、Header、Card、Button、Badge、搜尋欄與篩選器。
- 每個 AI Search 項目建議呈現名稱、狀態、資料來源、最近更新、建立者及進入詳情操作。
- 啟用／停用、發布狀態、使用量與權限欄位待確認。

### 9.4 AI Search Detail

- 可沿用頂層 Tab，建議分為「基本設定」、「招呼語與對話」、「外觀」、「資料管理」及「預覽」；實際 IA 待確認。
- 招呼語使用多行文字欄位與即時預覽；字數、變數、語系及安全規則待確認。
- 外觀設定沿用表單、Color field、圖片上傳與預覽卡片；品牌色可獨立設定，但管理介面本身仍遵循本設計系統。
- 資料管理沿用列表、Checkbox、Badge、批次操作、空狀態及同步狀態。
- 所有設定共享同一套儲存、版本、錯誤及未儲存提醒機制。

## 10. 命名與實作建議

建議以語意而非頁面綁定命名，方便跨模組共用：

```text
AppShell
SidebarNav
WorkspaceHeader
Breadcrumbs
ContentIdentityCard
ContentTabs
ModuleCard
TagCategoryRow
SelectableTagChip
StatusBadge
SourceBadge
MediaThumbnail
MetadataGrid
EvidencePanel
FormField
EmptyState
InlineFeedback
```

- Token 應集中於 Theme 層，元件不得散落硬編碼品牌色與陰影。
- 元件 Props 應描述語意（如 `status="success"`），避免直接傳入頁面專用色碼。
- Mock data 與正式 schema 分離；參考圖中的資料不可直接視為 API 定義。
- 文案長度需以繁中、英文與日文測試，避免只針對單一語系調寬。

## 11. 待確認清單

- 品牌正式色票、Logo 安全距離、指定字型及授權。
- 桌面最小寬度、是否支援平板／手機及正式斷點。
- Sidebar 的完整 IA、名稱與權限顯示規則。
- Content-level／片段層級／章節／場景之間的正式資料關係。
- AI 信心分數定義、顯示精度、排序方式與採用門檻。
- 每類標籤的最少／最多選取數、人工新增及審核流程。
- 分析、重新分析、儲存、版本建立與回復的完整生命週期。
- AI 來源與依據能否定位到字幕、時間碼或畫面。
- Loading、Empty、Error、權限不足與多人編輯衝突設計。
- AI Search 的發布流程、招呼語規則、外觀自訂範圍與資料同步狀態。
- 無障礙驗收標準、瀏覽器支援矩陣及效能指標。
